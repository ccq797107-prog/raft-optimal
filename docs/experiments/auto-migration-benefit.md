# 实验：自动迁移（Global Leader 切主）的收益评估

## 1. 实验目的与假设

**问题**：自动迁移（成本模型 + Move RPC 把 Global Leader 迁到负载域）相比**不迁移**，到底能为客户端带来多少收益？

**假设**：当全部客户端负载来自一个远离当前 Global Leader 的域时，把 GL 迁入该负载域后——读取从“一个跨域 RTT + 读屏障”降为**本地读**，写入从“到远端 GL 的完整跨域往返”降为**一个就近提交 RTT**——因此客户端可观测的读写延迟显著下降、闭环吞吐显著上升。

## 2. 实验设计（同集群、同负载的受控 A/B）

### 2.1 拓扑与延迟矩阵

三个域 `a`/`b`/`c`，每域 3 节点（`a1..a3` 等）。本地单向延迟 1ms，跨域单向延迟（往返为其两倍）：

| 链路 | 单向延迟 | 往返 RTT |
|---|---|---|
| `a <-> b` | 50ms | 100ms |
| `a <-> c` | 80ms | 160ms |
| `b <-> c` | 60ms | 120ms |

### 2.2 流程

- **初始 Global Leader**：域 `a`（节点 `a1`）。
- **工作负载**：全部请求 origin = 离初始 GL 最远的域 `c`（单向延迟最大，迁移收益最明显）。
- **条件 A（不迁移 / 基线）**：始终不发 Move，GL 留在域 `a`，测量 `c`-origin 客户端的写/读延迟与吞吐。
- **条件 B（自动迁移）**：外部成本模型（仅凭节点 Metrics 发布的窗口统计 + RTT 矩阵）确认推荐域 `c` 后，发起 GL-only Move，等集群重新收敛到新 GL，再用**完全相同**的 `c`-origin 负载测一遍。
- **公平性**：两种条件都用相同 origin 直连**当前 GL** 测量；节点按 `origin 域 ↔ GL 域` 注入客户端往返延迟（见 `Write`/`Read` 的 `sleepLink`）。A、B 之间唯一变化的就是 GL 的位置，从而把“迁移本身”的效果隔离出来。

## 3. 衡量指标

- 写延迟 p50 / p90（每条带新 requestId，杜绝幂等缓存造成的假低延迟）。
- 读延迟 p50 / p90（线性一致读）。
- 闭环吞吐：单客户端串行“写→读”完整往返，固定 4s 窗口内完成的往返数（pairs/s）。
- 成本模型预测 L_s：对比模型预测的收益与实测收益是否一致。

## 6. 结论

- 负载集中在远端域 `c` 时，自动迁移把 Global Leader 迁入该域后，读取（变为本地）与写入（变为就近提交）的客户端延迟均显著下降，闭环吞吐显著上升——证明自动迁移**确实有效且收益可观**。
- 成本模型基于真实发布的 Metrics **自主**识别出更优位置（推荐域 `c`），预测的成本下降方向与实测延迟下降一致。
- 全程不直接改写 leader 指针：迁移走 catch-up 追平 + 更高任期选举 + N-1 + fencing 的安全交接路径。
